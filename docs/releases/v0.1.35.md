# Autopsy 0.1.35

Fixes duplicate source-episode keys after a restore or migration.

Each write creates a source episode keyed `episode:<entity id>`. Entity ids only count up from the graph's current maximum. A restored or migrated graph keeps its old `episode:<n>` keys while its entity ids are renumbered, so a new write could create a second node with an existing episode key. Lookups by that key then became ambiguous, and every backup taken afterwards failed restore validation with `restore input contains 1 malformed or duplicate items`. Writes now check the key first and add a unique suffix when it is taken. Existing keys and memories are unchanged.

If `autopsy backup --status` reports `restore_validation_failed` after upgrading, find the duplicate with `autopsy restore <backup.json> --dry-run --offline`. The newer of the two episode nodes with the same key is the one to re-key.

Validation: 417 automated tests, including a regression test that fails without the fix.
