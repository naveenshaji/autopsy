# Autopsy 0.1.33

Autopsy keeps system-wide retrieval and uses the current project as a bounded ranking hint. Local Git worktrees and symlink aliases resolve to the same project for reads. Project filtering follows direct repository attribution and source episodes, avoiding shared-workspace paths that can mix unrelated projects. Stored repository nodes and memories are not merged or rewritten.

Task state now follows explicit evidence. `capture-outcome --completes KEY` closes an attempt or plan; `--reopens KEY` opens it again. `--answers` still resolves questions. Status omits completed, reverted, and superseded work from open sections and includes an evidence-backed resume object. Same-time contradictory state events remain visible as conflicts. Temporal validity and expiration are respected. Existing prose and `informed-by` links do not silently close work.

Context includes project labels, recorded dates, and available environment, commit, worktree, and verification metadata. Recorded dates are not live external verification. Current consult results exclude explicitly superseded or invalidated evidence before selecting the final hits; exact item, history, and timeline inspection remain available.

`autopsy evaluate SUITE.json --snapshot BACKUP.json --report REPORT.json` evaluates private gold questions against an isolated local restore. It reports evidence recall, ranking, stale or forbidden evidence, abstentions, latency, and context size. Add `--baseline REPORT.json` to reject newly failing cases; comparisons require matching suite and snapshot hashes. This is a lexical evidence evaluation, not an answer-accuracy or semantic-vector benchmark. No model judge or external API is used. Keep real questions and reports outside source control.

The initial private 50-question set improved from 38 to 48 passing cases, with evidence recall unchanged at 46/48 answerable questions and both abstention checks passing. Stale-evidence cases fell from 10 to zero. Median retrieval increased from 208 ms to 240 ms, with p95 from 390 ms to 488 ms. The suite was authored from source memories and still needs user review; these results do not establish general answer accuracy.

This release uses additive relations and read-time interpretation. Existing memory bodies, history, instruction files, backups, and iCloud settings remain preserved. iCloud Drive copy verification does not independently confirm Apple's server-side upload.

Validation: 393 automated tests, the fresh-install release check, installed health, and the five-sample benchmark with sync passed (9.9/10). The menu-bar release check now builds the explicitly selected checkout. The 9,278-item pre-change snapshot was restored in isolation with all 7,129 fact relations and 15,737 structural edges. Pre-install preservation checks found no changes to original content, metadata, tags, or creation/lifecycle fields.
