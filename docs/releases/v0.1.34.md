# Autopsy 0.1.34

Autopsy now runs on Linux and has a supported Linux install:

```bash
curl -fsSL https://raw.githubusercontent.com/naveenshaji/autopsy/main/scripts/install-release.sh | sh
autopsy install
```

The installer builds Autopsy into its own virtual environment under `~/.local` and puts `autopsy`, `autopsy-memory-worker` and `autopsy-memory-mcp` in `~/.local/bin`. On Linux it installs the CPU-only build of torch, because Autopsy's local models run on the CPU. The install is about 1.5 GB instead of the several GB of CUDA libraries in PyPI's default build. `AUTOPSY_TORCH_INDEX_URL=pypi` restores the default build. The installer picks Python 3.12, 3.13 or 3.14 and stops with a clear message for newer interpreters, which the embedded FalkorDB has no prebuilt packages for yet. It also explains a missing `venv` module and a `~/.local/bin` that isn't on `PATH`. The macOS menu bar app is no longer copied into Linux installs. See [Autopsy on Linux](../linux.md).

Data follows the platform convention: `~/Library/Application Support/Autopsy` on macOS (unchanged) and `$XDG_DATA_HOME/autopsy` (`~/.local/share/autopsy`) elsewhere. `AUTOPSY_APP_SUPPORT_DIR` still overrides both. The CLI, worker and MCP bridge resolve the same directory.

Claude Code sessions can be imported and recalled. `import-session --source claude-code` reads Claude Code transcripts. Re-importing a growing transcript rewrites only the exchanges that changed. Timestamps come from the conversation rather than the import time. Exchanges are split into passages that are searched and embedded on their own. `autopsy remember "<query>"` and the `autopsy_memory_remember` MCP tool recall conversations, passages and notes by meaning, grouped into moments with time, project and files.

Vector recall now runs. Missing vectors are computed after imports and on `autopsy sync`, and through the worker's `/memory/embed-pending` route. A memory's vector is cleared when its content changes, so it is recomputed. FalkorDB's cosine distance is converted to a similarity before ranking. While recall or consult requests are running, background imports and embedding passes wait between batches.

A new `onnx` provider runs the embedding and reranking models through ONNX Runtime instead of torch, using much less memory in a resident worker. Install it with the `onnx` extra. It produces the same vectors as sentence-transformers. Reranker scores follow the activation sentence-transformers would apply for each model, so thresholds carry over between providers. ONNX exports missing from a model already cached by sentence-transformers are downloaded on first use.

The MCP bridge accepts newline-delimited JSON over stdio, the framing Claude Code uses, as well as `Content-Length` framing, and answers in the client's framing. Before this, Claude Code could not call the bridge's tools.

macOS behaviour, the Homebrew formula's dependencies and the default models are unchanged.

Validation: 414 automated tests passed. A fresh Linux install was checked end to end on Fedora with Python 3.13: the installer, `autopsy install --smoke-test`, model warmup, write, `sync`, consult, `remember`, and MCP over newline-delimited stdio. CI gains a Linux install job that runs the installer from the checkout and checks for CPU-only torch and a passing install smoke test.
